# Кампус 0.2.0

Source release prepared on 2026-10-31. Activation evidence is recorded separately
in the deployment runbook; this note alone does not claim deployment.

- Groups, lecturers, rooms and configured VUC platoons share the same selection,
  search and comparison workspace. Rooms remain occupancy overlays.
- Day and Week default to stable schedule lanes in selection order. Display
  settings retain a persisted compact alternative. Shared lessons render once,
  including the personal exact-date military preview.
- Calendars use page vertical scrolling, compact controls and summaries, clear
  source colors, readable resource patterns, keyboard navigation and Today reveal.
- Direct removal, clearing hidden spotlights, drag reorder and history/focus
  behavior are integrated with the same typed selection identities.
- An implicit opening after all known selected lessons have ended chooses the
  next calendar day; explicit links and deliberate navigation retain their dates.
- Local PDF/DOCX import preserves original dates, exact document bytes and raw
  ambiguous evidence. One download per current document replaces repeated source
  blocks. The operator updater prepares a new explicit semester set atomically.
- Unknown, failed, expired and ambiguous data remain distinct from empty data.
  Coverage warnings and included/excluded calculation details remain available.

The existing cached timetable API, readable comparison links and legacy links
retain their contracts. Document dataset versioning is separate from the
application release number. The current document set is configured outside the
image and Git, as described in [the VUC workflow](../vuc.md).

The version in `package.json`, Git tag `v0.2.0`, GitHub Release and image version
label identify this release. Runtime images retain immutable full-commit-SHA
tags for provenance and rollback. The project remains in its pre-1.0 series.

Testing policy applicability was assessed against T3 Code, Grunge and Job
Harvester; see [the assessment](../reviews/2026-10-31-testing-policy.md).
