# Versioned timetable API и инструменты агента

Реализовано локально28.10.2026; deployment и подключение агента отдельно. Это
публичное **плановое** расписание. Студенты, реальные отметки, исключения и право
записи в университетский журнал принадлежат отдельной системе посещаемости.

## API

| GET                                  | Параметры                                                         |
| ------------------------------------ | ----------------------------------------------------------------- |
| `/api/v1/timetable/groups`           | `term`2–80 символов; `mode=cache` или `load`                      |
| `/api/v1/timetable/weeks/{group_id}` | `week=YYYY-MM-DD` — понедельник по Омску; `mode=cache` или `load` |

По умолчанию **cache**: только `Cache.Peek`, без source loader, обновления touched,
eviction, flight, retry или записи SQLite. Miss — `state:NOT_CACHED`, без `data`;
он не означает пустую неделю. Сохранённая успешная пустая неделя остаётся READY
с явным `data.lessons:[]`.

**load** выбирается явно для пользовательского запроса расписания. Ровно один
ключ поиска или недели передаётся существующим Cache.Get/Client. У свежего кеша
запросов к источнику нет; одновременные запросы одного ключа объединяются. Сохраняются
общие admission/spacing/Retry-After этого процесса. Нового scraper/client/worker нет.
Старые `/api/groups` и `/api/schedule/{id}` сохраняют совместимость и используют те
же ключи, кеш и client. Ни один режим не читает журнал посещаемости и не пишет отметки.

Ответ содержит `source:RUZ_PLANNED`, `mode`, `state`, `checked_at`, `expires_at`,
`stale`, `warning`, `snapshot_ref`, `data`, `membership:DISPLAY_ONLY`. Время проверки
не обновляется при чтении. Fingerprint `snapshot_ref` связывает ключ, check time и
точные данные; это не постоянный архив старых версий и не university binding.
Просроченный Peek возвращает последний имеющийся снимок с `stale:true`, без загрузки.
При load действуют прежние правила stale fallback, включая cutoff.

Пример: `/api/v1/timetable/weeks/1?week=2026-10-26&mode=cache`.
Идентификатор1 синтетический. Неизвестные/повторные query-параметры и неправильный
режим отклоняются. Недели ограничены двумя годами от текущей. Лимитер API общий
со старыми маршрутами. Эти public данные не требуют owner cookie и не предоставляют
приватную identity/command API посещаемости.

## Марвин / Hermes

Отдельный optional native-плагин `integrations/hermes_timetable` предоставляет:

- `omgtu_timetable_groups(term, mode?)`;
- `omgtu_timetable_week(group_id, week, mode?)`.

Это нативный адаптер инструментов Hermes поверх обычного service API, как интерфейс
агента; отдельный сетевой сервер протокола MCP не вводится. Имена не конфликтуют с
`campus_*` посещаемости. Четыре её семейства и модель подтверждения не меняются.
Сравнение свободных окон пока остаётся существующей чистой логикой сайта, не новым
инструментом. Автоматический импорт расписания/подгрупп не выполняется.

Для отдельной установки скопировать package с `plugin.yaml` в каталог плагина
Hermes и задать операторские настройки:

```text
CAMPUS_TIMETABLE_ORIGIN=https://campus.example
CAMPUS_TIMETABLE_OWNER_ID=<configured-owner-id>
```

Точный origin без path/порта/credentials; это не аргумент модели. Плагин использует
системную TLS-проверку, запрещает redirects, ограничивает время8s/ответ1MiB, не
повторяет запросы. Ошибки не возвращают raw exception/HTTP-body. Для обычных
source loads остаётся backend throttling; плагин его не реализует повторно.

Инструменты допускают только owner в Telegram DM из task-bound native ContextVars
с положительным message ID. CLI/cron/group/student/env-routing fallback запрещены
до открытия транспорта. Owner configuration не доказывает native origin запроса.
Плагин не добавляет Telegram handlers, бота, credentials или собственный source
клиент. Доступа к приватной системе посещаемости у него нет.

## Граница связи с посещаемостью

Клиенты могут читать запланированные пары здесь, фактический журнал — в его
приватном API. Совпадение времени/предмета и пустые subgroup IDs не устанавливают
соответствие людей, посещаемость, обе подгруппы или пару для замены. Эти данные
пригодны для отображения/сравнения; дальнейшая подготовка связей требует отдельного
точного анализа и подтверждения. Не отправлять частные ФИО/отметки в public Campus.

Для активации требуется отдельный релиз Campus и installation/configuration
native-плагина. Для отключения удалить/выключить этот plugin; старые public routes
и данные сохраняются. Нет миграции/изменения структуры DB. Тесты используют только
фикстуры, mutation traps и fake transport; живые source/агент не вызывались.
